# Miniature F1 prototype

User-selected design: clean F1-inspired body, approximately 0.60 m long and 0.25 m wide, front Ackermann steering using Chaos Vehicles, rear-wheel drive, and animated exposed suspension links. The original tandem remains a separate vehicle.

## Model and physical assumptions

The original procedural model is generated by `build_f1_meshes.py`. It is inspired by the supplied silhouettes, not an exact commercial F1 car or a dimensionally surveyed mechanism. Imported assets are in `/Game/Fable/F1Prototype`. The native actor is `/Script/RapyutaSimulationPlugins.MiniF1Car`.

| Parameter | Prototype value |
|---|---|
| Length | 60 cm |
| Width across tires | 25 cm (hub details extend approximately 3 mm beyond this) |
| Wheelbase | 37 cm |
| Wheel-center track | 20 cm |
| Tire diameter / width | 9 cm / 5 cm |
| Chassis mass setting | 3 kg |
| Wheel rotational mass setting | 0.08 kg each |
| Front steering configuration | Geometric Ackermann in Chaos simulation, hard 30-degree limit on each wheel |
| Rear steering | None |
| Drive | Rear wheels, single forward/reverse ratio |
| Engine torque / final drive | 0.60 Nm / 3:1 |
| Effective inertia scale (roll, pitch, yaw) | 5, 5, 1 relative to chassis collision hull |
| Suspension travel | 1.5 cm compression and 1.5 cm extension |
| Spring rate / damping ratio | 1,200 N/m per wheel / 0.8 |
| Downforce coefficient | Zero in this first prototype |

These are starting assumptions for a miniature simulation, not F1 engineering specifications or a validated 5 m/s setup. Mass, grip, torque and suspension need identification against the desired physical robot before any transfer of learned driving behavior.

The static-mesh chassis uses a convex collision hull. Chaos simulates wheel suspension and tire forces using ground traces. Wheel meshes and the visible wishbones, steering rods and pushrods animate from wheel steering/suspension output; they are not independent constrained rigid-body linkages. Cosmetic wings and wheel meshes have no separate collision. Obstacle clearance and track checks must use the complete vehicle envelope, not only chassis contact events. The wings currently change appearance; they do not model ground effect, DRS or aerodynamic downforce.

The F1 movement component applies Chaos spring/damper forces directly to its static chassis. It does not use skeletal suspension constraints or change global vehicle console settings. Suspension travel sets the ground-trace range; this prototype has no separate mechanical hard-stop constraints. The native wheel `SpringRate` value is 12 because UE 5.8's wheel setup multiplies it by 100, producing an internal spring coefficient equivalent to 1,200 N/m. This adapter is specific to the F1; the tandem physics components are unchanged.

## Controls and interface

Click Play and focus the viewport. I drives forward, K reverses, J/L steer left/right, Space commands braking. The initial keyboard speed target is 0.6 m/s. Releasing keys expires the command after 0.25 simulation seconds and commands braking. The car cannot rotate in place like the tandem; steering changes its direction while rolling.

F1 UDP port: `127.0.0.1:7449`. Tandems remain on 7447 and 7448. Two command modes:

```json
{"speed_mps":0.3,"steering_rad":0.15,"sensors":true}
```

Positive steering means left. This is a virtual steering demand; Chaos calculates different inner/outer front-wheel angles. It is not a yaw-rate command. Speed mode uses a simple feedback controller; realized speed is measured, not forced.

The custom steering calculation uses the 37 cm wheelbase and 20 cm wheel-center track. It replaces Chaos's fixed rack-stroke linkage, which oversteered at miniature scale. Full J/left gives left 30.00° and right 23.75°; full L/right gives left -23.75° and right -30.00°. The limits apply to the physical wheel forces and the visuals. UDP virtual angle requests are clamped to the bicycle-equivalent angle that produces a 30° inner wheel; Chaos's input shaping still affects partial commands.

```json
{"throttle":0.2,"steer":0.25,"brake":0.0,"sensors":true}
```

Throttle is signed [-1,1] (negative selects reverse), steer is [-1,1] (positive left), and brake is [0,1]. Send complete commands at approximately 20 Hz. The 5 m/s software limit is a control guard, not a proven operating speed; slopes can still cause overshoot. A 0.25-second command timeout applies braking in either mode. Reversal while rolling first commands braking.

```powershell
& 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/ThirdParty/Python3/Win64/python.exe' simulation_ml/integrations/rapyuta/f1_client.py --speed 0.3 --steering 0 --seconds 3
& 'C:/Program Files/Epic Games/UE_5.8/Engine/Binaries/ThirdParty/Python3/Win64/python.exe' simulation_ml/integrations/rapyuta/rgb_imu_client.py --port 7449 --frames 10
```

Replies use `f1_sensors_v1`, with actual chassis position, heading, speed, physics-valid flag, per-wheel contact, steering angle, suspension displacement and drive torque. Wheel order is front-left, front-right, rear-left, rear-right. The same RGB chunk requests and lidar/IMU payloads are available. The old tandem `v_mps/yaw_radps` command is deliberately not interpreted as steering.

World pose retains the existing bridge coordinates: `x=(UE_X-10000)/100`, `y=-UE_Y/100`, `z=UE_Z/100`; subtract 50 m from bridge X to match the 360 m reference track JSON. Exact pose/orientation fields remain labeled ground truth.

Sensors follow the new physical chassis. RGB mount is (10,0,12) cm from chassis origin, pointed 12 degrees down. Lidars are at (12,0,10) and (-12,0,10) cm, retaining their 3.5 m range. IMU is at chassis origin. Sensor mounting calibration differs from the tandem and must be read from metadata. Camera and lidar are ideal simulation models; no automatic lane perception or autonomous driving is included.

## Verified prototype behavior (2026-09-19)

Build package `_tb/171859463` passed Win64 Editor, Development and Shipping build checks. Installed editor DLL SHA-256: `CCB4686BB27A2C1E16668B81D2A5F6A4BE18B8165DB4E27B7F8C946485DFEDFF`.

`simulation_ml/integrations/rapyuta/validate_f1_live.py` passed in Play mode on the track. Evidence is in `simulation_ml/integrations/rapyuta/validation/f1_acceptance/summary.json`, `packets.json` and `camera.jpg`.

- All four wheels contacted the road at rest; measured chassis height variation was 1.28 mm during the stationary sample. The subsequent smooth-track update placed the saved start at UE (15000,0,261.17) cm, pitch 1.34°, yaw -46.08965634°, near full suspension extension. See `track/SMOOTH_TRACK.md` for the newer curb/runoff recovery checks.
- `validate_f1_steering.py` passed full-left/full-right tests in both angle and direct-input modes (120 samples). Inner wheel reached 30.00°, outer 23.75°, rear angles remained zero, and the angles satisfied the Ackermann cotangent relation. No sampled wheel exceeded 30° beyond floating-point tolerance.
- A 0.25 rad partial virtual steering demand produced front angles 0.140/0.130 rad, mirrored for the other direction; partial input shaping is retained.
- A 0.4 m/s target moved 0.665 m over the three-second phase, reaching 0.256 m/s. Speed tracking needs further tuning; the speed target is not imposed on the body.
- Braking reduced measured speed to about 0.005 m/s; the left-turn phase changed heading by 0.038 radians.
- After idle, reverse moved 0.528 m and reached -0.324 m/s. Stopping motor commands triggered timeout braking and reduced speed to about 0.005 m/s.
- RGB delivered 640x480 JPEG, both lidars returned 360 ranges, and IMU output was valid. Camera image was visually checked for track boundaries and vehicle-mounted perspective.

The low-speed driving tests used UDP commands. Keyboard mappings are implemented in the same native control path; physical key presses were not automated. The F1 explicitly wakes its static chassis on drive/steering demand, because Chaos's standard vehicle wake helper only handles skeletal bodies. The effective inertia scale is a stability tuning assumption, not a measured mass distribution. These checks do not establish a full autonomous lap, obstacle avoidance, racing-speed stability or calibrated real-world vehicle behavior.
